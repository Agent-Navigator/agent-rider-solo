Agent Rider Cloud WebSocket Reverse Connection

使用者只需一行指令安裝 agent-rider-srv。Server 不開放 inbound port，而是主動透過 outbound WSS 連到 Cloudflare；Browser 的 HTTP、SSE 與 WebSocket 經 Worker、Durable Object 與同一條連線多工轉發。

結論：可行，且符合一鍵安裝產品模型；但這不是普通 WebSocket proxy，而是產品自行維護的 application-level reverse tunnel。每台 node 必須使用一個 Durable Object，普通 Worker 記憶體不能作為連線 registry。

Durable Object ID 建議使用 hash(account_id + node_id)。Connector 與該 node 的 browser connections 都會到同一個 object，避免因 Worker isolate 或地區不同而找不到連線。

Hibernation 可用：server 雖然主動向外連線，但 Durable Object 是接受 WebSocket 的 server 端。不要讓 Durable Object 主動建立 outbound WebSocket；outbound socket 無法 hibernate。

一行安裝與 enrollment

curl -fsSL https://rider.example.com/install.sh \
  | sudo bash -s -- --enroll-token ar_join_xxxxx
  1. 使用者登入 Cloud UI，建立一次性、短效 enrollment token。
  2. Installer 下載預編譯 binary，建立 system service。
  3. agent-rider-srv 在本機建立 device keypair；私鑰不離開 server。
  4. 呼叫 POST /v1/nodes/enroll，交換 node_id 與長期 device credential。
  5. Credential 寫入 root-only 檔案，一次性 token 立即失效。
  6. Service 主動建立以下連線：
GET /v1/connect HTTP/1.1
Upgrade: websocket
Authorization: Bearer <device-credential>
X-Agent-Rider-Node: <node-id>
X-Agent-Rider-Protocol: 1

Server 只需 outbound TCP 443，不需要 public IP、DNS、port forwarding 或使用者設定 Cloudflare Tunnel。

WebSocket 單一 message 上限目前是 32 MiB。實作應使用約 32–64 KiB binary chunks，保留 per-channel flow control，而且不可先把完整 upload 或 response 讀進 Worker 記憶體。

與現有 backend 整合

保留 API contract

React 繼續使用既有 /store、/api、SSE 與 terminal WebSocket。SQLite、PTY、Hermes 和 tmux 留在 node。

Connector 是本機 adapter

整合進 agent-rider-srv；收到 OPEN 後連到 loopback backend。目前 backend 已只監聽 127.0.0.1:5174，適合直接保留。

移除 production Vite

React assets 交給 Worker Static Assets；Guacamole、Hermes UI proxy 與 auth-start 搬進 server runtime。

Node 不可互相 failover

SQLite、filesystem、Hermes session 與 tmux 屬於指定 node。Offline 時回 503 Node offline，不可送去另一台。

可靠性設計

  • Connector 使用 exponential backoff 加 jitter 自動重連。
  • 每次連線帶遞增 generation；新連線完成後關閉 stale connector。
  • 每個 channel 使用不可重複 request ID；GET 可重試，POST 必須去重。
  • Worker deploy、DO 重啟與網路切換均視為正常事件，protocol 支援 RESET 與重新 attach。
  • Terminal 重連 attach 原有 tmux；Hermes SSE 使用 stream status/replay 恢復。
  • 設定 per-node channel、頻寬、upload size、queue bytes 與 idle timeout 上限。

初版可用一條 multiplexed socket；正式版建議拆成 control 與 bulk 兩條 connector sockets，避免大檔案造成 terminal head-of-line blocking。

安全邊界

風險必要控制
未授權 node 存取每次 browser request 驗證 account ownership，不能只依賴 node ID
Device credential 洩漏短效 enrollment、rotate/revoke、root-only storage
Connector 成為 SSRF proxy只允許固定 localhost route table，不接受任意 host 或 port
Replay／重送generation、request ID、timestamp 與 server-side deduplication
資源耗盡per-account/node/channel limits、queue caps 與 cancellation
協定不相容protocol/build version 與 capability negotiation

Device identity 證明「這是已 enrollment 的 server」，browser identity 證明「目前使用者有權操作它」。Durable Object ID 本身不是 credential。

限制、成本與交付

  • 每台 node 一個單執行緒 Durable Object；不要讓所有客戶共用同一 object。
  • 單一 object 約有每秒 1,000 個簡單 request 的 soft limit，個人／小團隊 node 足夠。
  • Worker/DO 記憶體為 128 MB，所有 body 必須 streaming。
  • Hibernation 可降低 idle connector duration；WebSocket messages 仍會計量。
  • 正式 SaaS 建議 Workers Paid，並在產品層實作 quota。

核心 MVP 約 3–4 週；完整 production-grade 版本合理估計為 5–8 週。主要風險是 multiplex flow control、長串流恢復與安全 enrollment，不是 WebSocket handshake。

建議下一步

  1. 先做 terminal-only vertical slice，證明 server outbound WSS → DO → browser。
  2. 固定 framing、generation 與 flow control 後，再加入 HTTP/SSE。
  3. 保留現有 frontend/backend API contract，避免同時重寫 UI 與 transport。
  4. Connector 優先整合進未來 Rust agent-rider-srv，Node 版先作相容實作。
  5. 斷線、deploy、100 MB transfer 和 terminal 壓測完成後，才開放公開 enrollment。
